How it works

When you create a ticket, the help desk sends it to Agent Mesh as a signed webhook. The ticket-intake workflow then triages it, works out when the customer must hear back, drafts a first reply, and decides whether to escalate. Two steps use an LLM; the deadline, the routing and the write-back are plain code and rules, so they give the same result every time. The ticket updates below in 15 to 30 seconds.

How the decision model works

Each ticket goes to the classify decision node in the ticket-decision workflow. The node sends the ticket to a decision model (ticket-router) in one call, and the model answers all five questions below at once, with typed answers and confidence scores. A decision model only classifies; it does not write text. So most tickets get a canned acknowledgement for their department and are written back without an LLM, and only critical or uncertain tickets go on to the support-responder agent for a drafted reply.
